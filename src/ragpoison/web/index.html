Research tool for stores you own. Payloads are inert marker strings.

Target

Where retrieval is measured. Local uses the bundled ChromaDB store. Remote calls any RAG service over HTTP that returns ranked documents for a query.

lab is the collection that gets poisoned; clean stays untouched as a baseline. Rebuilding drops every injected document.

Response mapping and headers

Contract: POST {query, k} → {"results": [{"doc_id", "score", "text"}]}, best first; ingest is POST {doc_id, text}. A second instance (ragpoison --workdir other serve --port 8766) serves exactly this at /rag/query and /rag/ingest. Poison is recognised by the injected ids or the marker in the text.

Craft poison

White-box greedy search for text whose embedding sits on the centroid of the attacker's topic queries. Runs offline; nothing is written to any store.

Validate offline

Predict what injection would do, using the same chunker and model in memory. No store is touched. In the reference run this matched the live injection exactly.

Defenses

Detection checks look at the incoming documents' embeddings before they are written. Reranking is measured in Inject & measure with the rerank box ticked.

Run everything

The full pipeline on the local store: rebuild, baseline, craft, validate, inject, measure, rerank, both detection checks. About four minutes on four CPU cores; same as ragpoison run.

API

Everything in this UI is a REST call. Interactive docs: /docs, schema: /openapi.json.

Rules

  • State-changing calls must send Content-Type: application/json; cross-origin calls are refused.
  • With --token, send Authorization: Bearer <token>.
  • Long operations return {"job_id"}. Poll GET /api/jobs/{id}?since=N for status, new log lines and the result.
  • Every measuring call takes a target: {"kind":"local","collection":"lab"} or {"kind":"remote","base_url":"…","query_path":"/query","ingest_path":"/ingest"}.
